= Crea un piano di distribuzione per VMware Cloud su AWS utilizzando VMware workloads migration advisor
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Accedi a NetApp Workload Factory per accedere a VMware migration advisor. Segui i passaggi della procedura guidata per creare un piano di distribuzione o un piano di migrazione personalizzato in base alle tue esigenze.

Quando esegui la migrazione a VMware Cloud, puoi utilizzare l'assistente alla migrazione per migrare il tuo ambiente locale corrente vSphere a VMWare cloud.

Tieni presente che devi disporre di un nome utente e di una password per accedere a Workload Factory. Se non hai accesso, crea subito un account. Consulta le istruzioni link:quick-start-vmware.html["qui"].



[[create-a-deployment-plan-based-on-an-on-premises-vsphere-environment]]
== Crea un piano di implementazione basato su un ambiente vSphere on-premises

Puoi migrare le configurazioni correnti delle macchine virtuali negli ambienti on-premises vSphere in macchine virtuali in VMware Cloud on AWS e utilizzare file system Amazon FSx for NetApp ONTAP personalizzati come datastore esterni.

.Requisiti
* Devi aver creato il file di inventario dai tuoi sistemi esistenti utilizzando il collector VM di Migration Advisor (file .csv) o utilizzando RVTools (file .xlsx).
* Devi avere accesso al file di inventario dal sistema da cui accedi a Workload Factory.


.Passaggi
. Accedi al link:https://console.netapp.com["NetApp Console"^].
. Seleziona il menu image:workloads-menu-icon.png["L'icona del menu hamburger serve per passare a Workloads, la voce di menu di Workload Factory"], *Workloads* > *VMware*.
+
Compare il centro di pianificazione.

. Seleziona *Pianifica e crea VMC*.
. Seleziona il tipo di file di inventario che utilizzerai per popolare Workload Factory con la configurazione corrente della tua VM e seleziona *Avanti*.
+
** Seleziona *Usa il raccoglitore dati VMware di migration advisor* per utilizzare il file .csv che hai creato con il raccoglitore dati VMware.
** Seleziona *Use RVTools* per utilizzare il file .xlsx creato con RVTools.


+
Compare la pagina "Preparazione all'onboarding di VMware Cloud".

. Nella sezione _Carica configurazione VM_, seleziona image:button-upload-file.png["il pulsante di caricamento"] e seleziona il file che desideri utilizzare.
+
** Quando utilizzi Migration advisor VM collector, seleziona il file .csv.
** Quando utilizzi RVTools, seleziona il file .xlsx.


+
La sezione di riepilogo delle VM si popola dal file di inventario per riflettere il numero di VM e la capacità di archiviazione totale.

. Nella sezione _Considerazioni sull'inventario delle VM_, seleziona le opzioni per filtrare l'elenco delle VM che desideri migrare.
+
.. *Considera le VM*: indica quali VM verranno estratte dal file .csv in base al loro stato di alimentazione. Puoi includere tutte le VM o solo quelle accese, spente o sospese.
.. *Archiviazione VM da considerare*: Seleziona se le dimensioni dei datastore creati per ogni VM integrata si basano sulla dimensione attualmente utilizzata (consigliato) o sulla dimensione allocata.
+
I datastore esterni saranno implementati utilizzando i volumi del file system Amazon FSx for NetApp ONTAP.

.. *Memoria VM da considerare*: Seleziona se la memoria allocata per ogni VM aggiunta viene dimensionata in base alla dimensione attualmente utilizzata (consigliato) o alla dimensione di cui è stato eseguito il provisioning.


. Nella sezione _Configurazione della distribuzione di VMware Cloud on AWS_, inserisci i dettagli relativi alla configurazione richiesta di VMware Cloud on AWS.
+
.. *Regione*: Seleziona la regione in cui verranno distribuite le VM e i file system Amazon FSx for NetApp ONTAP.
+
Per prestazioni ottimali ed efficienza in termini di costi, in genere si tratta della stessa regione in cui è distribuito il tuo VMware Cloud on AWS SDDC esistente.

.. *Requisiti di prestazioni stimati per le VM*: Questa opzione è disponibile solo quando utilizzi RVTools. Il VM collector di Migration advisor acquisisce queste informazioni dal tuo ambiente. Fornisci i seguenti parametri medi delle prestazioni per ogni macchina virtuale che vuoi applicare alle nuove VM che distribuirai:
+
*** *IOPS medi per VM*: Inserisci il numero di IOPS richiesti per i tuoi file system. Se non sei sicuro, puoi usare il valore predefinito di 3 IOPS per GiB di storage SSD per i file system Amazon FSx for ONTAP. Ad esempio, se implementi 2.000 GiB di capacità, questo si tradurrà in 6.000 IOPS. Ti consigliamo di iniziare con un'impostazione IOPS più bassa. Puoi aumentare gli IOPS SSD di cui è stato effettuato il provisioning dopo la creazione del file system, man mano che i carichi di lavoro vengono migrati o implementati.
*** *Dimensione media del blocco I/O*: la dimensione di ciascun blocco contenente operazioni di lettura o scrittura. La dimensione predefinita è 4 KB. Una dimensione del blocco maggiore può essere più adatta per carichi di lavoro di grande lettura sequenziale e scrittura. Una dimensione del blocco minore può offrire prestazioni migliori per carichi di lavoro che eseguono piccole scritture casuali su file sparsi o file di grandi dimensioni.
*** *Rapporto medio di scrittura*: la percentuale di operazioni di scrittura per i tuoi carichi di lavoro. Il rapporto predefinito è del 30% di scritture e del 70% di letture.




. Nella sezione _Considerazioni sulla capacità di archiviazione delle VM_, seleziona una delle opzioni di archiviazione disponibili.
+
.. *Rapporto medio di riduzione dei dati*: scegli tra i tre valori comuni di riduzione dei dati. Seleziona "1:1 - Nessuna riduzione", "1:1.25 - riduzione del 20%" o "1:1.5 - riduzione del 33%".
.. *Percentuale di margine di capacità*: Inserisci la percentuale di crescita della capacità da aggiungere alla capacità dei tuoi file system FSx for ONTAP.
+
Tieni presente che se selezioni un valore inferiore al 20% non potrai creare snapshot del volume per la protezione e i backup a lungo termine.



. Seleziona *Next* e viene visualizzata la pagina "VMware cloud on AWS node configuration".
+
Questa pagina ti consente di definire la configurazione del cluster VMware cloud on AWS utilizzando un'analisi dei risparmi stimati e il tipo di nodo consigliato. Puoi configurare quanto segue:

+
.. *Architettura vSAN*: Seleziona se vuoi usare l'architettura vSAN Express Storage Architecture (ESA) o l'architettura vSAN Original Storage Architecture (OSA).
.. *Tolleranza ai guasti vSAN*: seleziona il livello di tolleranza ai guasti richiesto per le VM. Puoi scegliere "Auto", che è l'opzione consigliata, oppure uno dei vari livelli RAID disponibili.
+
*** RAID-1 (FTT 1): consiste in una copia esatta (o mirror) di un insieme di dati su 2 o più dischi.
*** RAID-5 (FTT 1): consiste in uno striping a livello di blocco con parità distribuita - le informazioni di parità sono distribuite tra 3 o più dischi e può sopravvivere al guasto di un singolo disco.
*** RAID-5 (FTT 2): consiste in uno striping a livello di blocco con parità distribuita - le informazioni di parità sono distribuite tra 4 o più unità e il sistema può sopravvivere a due guasti simultanei dei dischi.
*** RAID-6 (FTT 2): estende RAID 5 aggiungendo un ulteriore blocco di parità; pertanto, utilizza lo striping a livello di blocco con due blocchi di parità distribuiti su tutti i dischi membri. Richiede 4 o più unità e può sopravvivere a due guasti simultanei dei dischi.


.. *Elenco di selezione della configurazione dei nodi*: seleziona un tipo di istanza EC2 per i nodi.


. Seleziona *Avanti* e la pagina "Seleziona macchine virtuali" mostra le VM che corrispondono ai criteri specificati nella pagina precedente.
+
.. Nella sezione _Criteri di selezione_, seleziona i criteri per le macchine virtuali che intendi distribuire:
+
*** Basato sull'ottimizzazione dei costi e delle prestazioni
*** In base alla possibilità di ripristinare facilmente i tuoi dati con snapshot locali per scenari di ripristino
*** Sulla base di entrambi i criteri: il costo più basso, pur offrendo buone opzioni di ripristino


.. Nella sezione _Macchine virtuali_, le VM che corrispondono ai criteri specificati nella pagina precedente sono selezionate (contrassegnate). Seleziona o deseleziona le VM se vuoi eseguire l'onboarding o migrare meno o più VM in questa pagina.
+
La sezione *Configurazione consigliata* verrà aggiornata se apporti modifiche. Tieni presente che, selezionando la casella di controllo nella riga di intestazione, puoi selezionare tutte le VM in questa pagina.

.. Seleziona *Avanti*.


. Nella pagina *Piano di distribuzione del datastore*, verifica il numero totale di VM e datastore consigliati per la migrazione.
+
.. Seleziona ciascun Datastore elencato nella parte superiore della pagina per visualizzare le modalità di provisioning dei datastore e delle macchine virtuali.
+
Nella parte inferiore della pagina vedi la VM di origine (o più VM) per cui verranno predisposte questa nuova VM e il datastore.

.. Una volta compreso come verranno distribuiti i tuoi datastore, seleziona *Avanti*.


. Nella pagina *Rivedi il piano di distribuzione*, esamina il costo mensile stimato per tutte le macchine virtuali che intendi migrare.
+
Nella parte superiore della pagina è descritto il costo mensile per tutte le VM distribuite e i file system Amazon FSx for NetApp ONTAP. Puoi espandere ogni sezione per visualizzare i dettagli di "Recommended Amazon FSx for ONTAP file system configuration", "Ripartizione stimata dei costi", "Configurazione dei volumi", "Ipotesi di dimensionamento" e "Note legali" tecniche.

. Quando sei soddisfatto del piano di migrazione, hai diverse opzioni:
+
** Seleziona *Deploy* per distribuire i file system FSx for ONTAP a supporto delle tue VMs. link:deploy-fsx-file-system.html["Scopri come implementare un file system FSx for ONTAP"].
** Seleziona *Scarica il piano > Distribuzione VM* per scaricare il piano di migrazione in formato .csv, così potrai usarlo per creare la tua nuova infrastruttura dati intelligente basata sul cloud.
** Seleziona *Scarica piano > Report del piano* per scaricare il piano di migrazione in formato .pdf, così puoi distribuire il piano per la revisione.
** Seleziona *Esporta piano* per salvare il piano di migrazione come modello in formato .json. Potrai importare il piano in un secondo momento e utilizzarlo come modello per la distribuzione di sistemi con requisiti simili.
